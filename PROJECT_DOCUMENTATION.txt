1. PROJECT OVERVIEW
================================================================================

The Resume Screening Agent is an AI-powered, automated resume screening system
that ranks candidates against a given job description (JD). Instead of relying
solely on simple keyword matching, the system combines:

  - Natural Language Processing (NLP) semantic similarity (Sentence-BERT)
  - TF-IDF statistical text similarity
  - Hand-engineered features (skills, experience, education, resume structure)

These 17 features are fed into an XGBoost regression model that predicts a
relevance score (0-100) for each resume. Resumes are then ranked from most
to least relevant.

The core philosophy is INTERPRETABILITY — every feature that contributes to a
candidate's score can be inspected, making the system auditable by recruiters
and hiring managers. Unlike black-box deep learning approaches, the reasons
behind every ranking are transparent.

================================================================================

DETAILED STEP-BY-STEP FLOW:
---------------------------

Step 1 — Resume Parsing (parse_resume.py):
    The system auto-detects file format by extension and uses the appropriate
    parser:
      • .pdf  → pdfplumber (iterates over pages, extracts clean text)
      • .docx → python-docx (extracts paragraph text)
      • .txt  → Python built-in open() with UTF-8

    All text is cleaned (normalized whitespace, non-ASCII stripped).

Step 2 — Job Description Parsing:
    The JD is read as plain text from a .txt file.

Step 3 — Feature Extraction (extract_features.py):
    For each resume-JD pair, 17 numerical features are computed:
      • Semantic similarity  — Sentence-BERT cosine similarity
      • TF-IDF similarity     — TF-IDF cosine similarity
      • Skill-based features  — matched_skills, missing_skills,
                                 skill_match_ratio, extra_skills
      • Experience features   — resume_years, required_years, experience_fit
      • Education features    — resume_level, required_level, education_fit
      • Section presence      — has_experience, has_education, has_skills,
                                 has_projects, has_certifications

Step 4 — Similarity Scoring (similarity.py):
    The SimilarityScorer class manages:
      • Sentence-BERT model (all-MiniLM-L6-v2) for semantic similarity
      • TF-IDF vectorizer for statistical keyword similarity
    Batch encoding is used: the JD is encoded once, all resumes are encoded
    together, then pairwise cosine similarities are computed efficiently.

Step 5 — Ranking (rank_candidates.py):
    The ResumeRanker class:
      1. Loads the trained XGBoost model, StandardScaler, and feature names
      2. Computes all 17 features for each resume-JD pair
      3. Scales features using the pre-fitted StandardScaler
      4. Predicts scores via XGBoost (clipped to 0-100)
      5. Returns a DataFrame sorted by score descending

Step 6 — Output:
    Results are saved as a CSV file with all feature values, the predicted
    score, and the rank for each resume. The top-ranked resume has rank=1.

3. FEATURES EXTRACTED FROM RESUMES
================================================================================

The system extracts 17 features per resume-JD pair. Here is each feature
explained:

────────────────────────────────────────────────────────────────────
FEATURE                    TYPE      DESCRIPTION
────────────────────────────────────────────────────────────────────
semantic_similarity        Float     Sentence-BERT cosine similarity
                                     between resume and JD (0-1).
                                     Captures overall meaning overlap
                                     beyond exact keywords.

tfidf_similarity           Float     TF-IDF cosine similarity (0-1).
                                     Captures keyword/term overlap
                                     weighted by rarity.

matched_skills             Integer   Count of skills from the JD that
                                     appear in the resume.

missing_skills             Integer   Count of JD-required skills NOT
                                     found in the resume.

skill_match_ratio          Float     matched_skills / total JD skills.
                                     A 0-1 ratio; 1.0 = perfect match.

extra_skills               Integer   Count of skills in the resume
                                     that are NOT required by the JD.
                                     Indicates additional capabilities.

resume_experience_years    Integer   Total years of experience extracted
                                     from the resume (max 40).

required_experience_years  Integer   Minimum years required by the JD.

experience_fit             Float     If resume_years >= required_years
                                     → 1.0, otherwise ratio score (0-1).

resume_education_level     Integer   Highest education detected:
                                     1=High School, 2=Associate,
                                     3=Bachelor, 4=Master, 5=PhD.

required_education_level   Integer   Education level required by the JD
                                     (same 1-5 scale).

education_fit              Float     If resume_level >= required_level
                                     → 1.0, otherwise ratio score (0-1).

has_experience             0/1       Boolean: does the resume contain an
                                     "Experience" or "Work History" section?

has_education              0/1       Boolean: does the resume contain an
                                     "Education" section?

has_skills                 0/1       Boolean: does the resume contain a
                                     "Skills" section?

has_projects               0/1       Boolean: does the resume contain a
                                     "Projects" section?

has_certifications         0/1       Boolean: does the resume contain a
                                     "Certifications" section?
────────────────────────────────────────────────────────────────────

SKILL EXTRACTION:
-----------------
The system maintains a predefined set of ~80 technical skills:
  Python, Java, JavaScript, TypeScript, C, C++, C#, Go, Rust, Ruby, PHP,
  Swift, Kotlin, Scala, R, MATLAB, SQL, NoSQL, MongoDB, PostgreSQL, MySQL,
  React, Angular, Vue, Node.js, Django, Flask, Spring, Express, .NET,
  Docker, Kubernetes, AWS, Azure, GCP, Terraform, Ansible, Jenkins,
  Git, Linux, Bash, REST, GraphQL, HTML, CSS, Selenium, Pandas, NumPy,
  Scikit-learn, TensorFlow, PyTorch, Keras, NLP, Computer Vision,
  Deep Learning, Machine Learning, Data Science, Spark, Hadoop, Kafka,
  Redis, RabbitMQ, Elasticsearch, Tableau, Power BI, Excel, Agile,
  Scrum, JIRA, CI/CD, Microservices, API, OOP, etc.

And ~15 soft skills:
  Communication, Leadership, Teamwork, Problem Solving, Critical Thinking,
  Time Management, Adaptability, Creativity, Collaboration, etc.

Skills are extracted via regex with word-boundary matching against the
resume text, ensuring "Java" doesn't match "JavaScript".

5. EXPECTED OUTPUT
================================================================================

The system produces a CSV file (default: ranked_candidates.csv) with these
columns:

  rank, filename, score, semantic_similarity, tfidf_similarity,
  matched_skills, missing_skills, skill_match_ratio, extra_skills,
  resume_experience_years, required_experience_years, experience_fit,
  resume_education_level, required_education_level, education_fit,

  has_certifications

The file is sorted by score in descending order, so:
  • rank 1 = the best-matching candidate

9. DESIGN PATTERNS & ARCHITECTURAL DECISIONS
================================================================================

WHY ENGINEERED FEATURES + XGBOOST INSTEAD OF END-TO-END DEEP LEARNING?
────────────────────────────────────────────────────────────────────────
  1. Interpretability — every feature can be inspected. A recruiter can
     see exactly why a candidate scored 64 vs 38.
  2. Data efficiency — 2000 synthetic samples are enough; deep learning
     would require millions of labeled resume-JD pairs.
  3. Deployment simplicity — a small JSON model + scaler, no GPU needed.
  4. Audit trail — each feature value is written to the output CSV.

WHY SENTENCE-BERT + TF-IDF (DUAL SIMILARITY)?
───────────────────────────────────────────────
  • Sentence-BERT captures semantic meaning (e.g., "built ML pipelines"
    and "developed machine learning systems" match even with no shared
    keywords).
  • TF-IDF captures exact keyword overlap (e.g., "Docker" and "Kubernetes"
    are exact tokens that should match precisely).
  • Together they complement each other — semantics + keywords.

WHY SYNTHETIC TRAINING DATA?
──────────────────────────────
  • No public dataset of labeled resume-JD pairs with relevance scores.
  • Synthetic data provides controlled, noise-injected training samples.
  • The heuristic scoring function (50% skills, 30% experience, 20%
    education) encodes domain knowledge about what matters in hiring.
  • Real labeled examples (like Bhuvan's resume) can be mixed in to
    calibrate the model.

WHY PDFPLUMBER OVER PYMUPDF OR PYPDF2?
───────────────────────────────────────
  • PyMuPDF (fitz) — fastest but has AGPL licensing concerns.
  • PyPDF2 — free but struggles with complex layouts and multi-column text.
  • pdfplumber — accurate layout preservation, per-page iteration, clean
    API, and MIT license.

DESIGN PATTERNS USED:
──────────────────────
  • Pipeline Pattern      — Sequential stages: parse → extract → score → rank
  • Strategy Pattern      — Format-specific parsers dispatched by extension
  • Object-Oriented Core  — SimilarityScorer and ResumeRanker encapsulate
                             stateful model objects
  • Functional Utilities  — Pure functions for feature extraction (testable)
  • Batch Processing      — Single JD encoding, multi-resume encoding
  • CLI + API Dual Mode   — Both command-line and Python library interfaces

11. LIMITATIONS & FUTURE WORK
================================================================================

LIMITATIONS:
  • Skill extraction is regex-based — it won't detect skills phrased
    differently from the predefined list (e.g., "built neural nets" vs
    "Deep Learning").
  • No OCR support — scanned/image-based PDFs cannot be parsed.
  • No structured section parsing — the system detects section presence
    but doesn't extract the content of each section separately.
  • Single-JD ranking — currently ranks against one JD at a time.
  • English-only — no multilingual support.
  • Synthetic data bias — the model inherits the biases of the heuristic
    scoring function used to label training data.

FUTURE ENHANCEMENTS:
  • Named Entity Recognition (NER) for company names, universities, job titles
  • OCR support for scanned PDFs (Tesseract integration)
  • Multi-JD matching — rank one resume against multiple JDs simultaneously
  • Web UI / dashboard for interactive ranking
  • API server (FastAPI) for integration with ATS/HR systems
  • Support for additional formats: .rtf, .odt, .html
  • Fine-tuned domain-specific embedding model on resume data
  • Active learning — incorporate recruiter feedback to improve the model
  • Experience timeline parsing — extract individual job durations
